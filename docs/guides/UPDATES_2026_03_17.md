### 1. Team References: Foreign Key Architecture ✅

**Your Assessment**: Correct and optimal for your data volume.

**Architecture Decision**:

- **Database Level**: Pure relational with foreign keys (`homeTeamId`, `awayTeamId`)
- **API Level**: Embedded Team objects for developer convenience
- **Rationale**: At 40-50 games/year, this hybrid approach is ideal—no N+1 queries, maintains referential integrity, minimal data overhead (~2-3 KB/game)

**Files Updated**:

- ✅ `data-model.md`: Confirms FK structure (no changes needed—already optimal)
- ✅ `game-contract.md`: API examples show embedded Team objects
- ✅ `ARCHITECTURE_DECISIONS.md`: New file (ADR-001) documents this decision

**Benefits**:

- ✅ Relational database integrity (no orphaned games)
- ✅ Single API request returns complete game data
- ✅ Scales seamlessly to multi-team tournaments
- ✅ Future-proof without schema migration

### 3. Date of Birth: ISO 8601 Format ✅

**Previous**: `DateTime?` (includes time component—unnecessary)  
**Updated**: `String?` in ISO 8601 format `YYYY-MM-DD`

#### Changes:

**data-model.md** — Player Entity:

```prisma
dateOfBirth  String?  // ISO format "YYYY-MM-DD", NULL if undefined
```

**Validation Rules Updated**:

- Format: `YYYY-MM-DD` only (no time component)
- Example: `"1990-05-15"` or `null`
- UTC: All dates interpreted on UTC calendar (no timezone issues)

**Age Calculation** (Frontend Responsibility):

```typescript
function calculateAge(dateOfBirth: string | null): number | null {
  if (!dateOfBirth) return null;
  const today = new Date();
  const [year, month, day] = dateOfBirth.split("-").map(Number);
  let age = today.getFullYear() - year;
  if (
    today.getMonth() < month - 1 ||
    (today.getMonth() === month - 1 && today.getDate() < day)
  ) {
    age--;
  }
  return age;
}
```

**Benefits**:

- ✅ Clean date-only representation
- ✅ No timezone confusion
- ✅ Easy age calculation on frontend
- ✅ Optional field (NULL if not provided)
